# grounded-mcp v0.2 — HTTP mode: the stdio caveat becomes a shipped feature

v0.1's honesty section said it plainly: over stdio, client and server run as the same user, so entitlement profiles demonstrate a deployment pattern rather than defend against a hostile peer. v0.2 closes that boundary. Over streamable HTTP, each client presents a bearer token, the token maps to an entitlements profile, and every tool call resolves through the VERIFIED identity. Nothing about a client's access is a client claim.

## How it works

Run with `GROUNDED_TRANSPORT=http` and a `GROUNDED_TOKENS` file. Tokens are stored as sha256 hashes (the file is config, not a secret); generate a hash with `python -m grounded_mcp.authz <raw-token>`. Each token row names a `client_id` and a `profile`; the server builds ONE INDEX PER PROFILE, so enforcement stays index-level exactly as in v0.1 — denied content is never scored for a profile, whoever asks.

```yaml
tokens:
  - sha256: "9f86d081..."
    client_id: analytics-team
    profile: staff
```

The SDK's OAuth resource-server machinery does the transport half: unauthenticated requests get a 401 with RFC 9728 discovery metadata; verified tokens reach the handlers, where `get_access_token()` supplies the identity the profile is resolved from.

## Fail-closed rules (all tested)

An unknown token is a 401, never a fallback profile. An EMPTY token file refuses to start the server (an endpoint that denies everyone tempts someone to add a default). A verified client missing from the token map is a server misconfiguration and errors rather than guessing. HTTP mode without a token file refuses to start: serving a network endpoint unauthenticated would silently WIDEN v0.1's boundary instead of closing it.

## Tested over the wire, not just in-process

v0.1.1 taught this project that an eval suite's coverage is bounded by the path it exercises (the worker-thread bug was invisible to in-process evals). So v0.2's integration tests run a real HTTP server and probe it as real clients: a staff token sees `internal/`, a contractor token gets zero results for the same request and cannot distinguish a denied note from a nonexistent one, the restricted-content leakage probe runs over the wire, and a bad token is rejected at the transport. The in-process eval suite (retrieval, abstention, leakage, redaction) is unchanged and still gates CI.

## stdio mode is unchanged

Local single-user use keeps working exactly as before — `GROUNDED_PROFILE` applies, no tokens involved, and the honesty note still applies to that mode. HTTP is where multi-client entitlement enforcement is real.

## Still deliberately out (v0.3 candidates)

Hybrid semantic retrieval remains the flagged upgrade, and it lands only with a published eval delta against the BM25 baseline. Token scopes beyond `read` are unneeded while the server is read-only by design.
